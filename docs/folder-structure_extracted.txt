Project Folder Structure
Version 1.0 | August 2026
This document lays out the full repository structure for Medikart, organized around how the project will actually
be hosted: a Next.js storefront and an Express API running as managed processes on the VPS, and a
React/Vite admin dashboard built to static files served by Nginx. The tree below is followed by a
plain-language explanation of what each significant file and folder is for.
Folder Structure
Real .env files are shown because they genuinely exist on disk — the root .gitignore is what keeps them,
node_modules, and build output out of Git. Only what's actually committed to the repository is meant to be
tracked; everything else is either a secret, reproducible from a lockfile, or generated at build/deploy time.

Root & Deployment Files
nginx/medikart.conf Routes traffic: the storefront domain to the Next.js PM2 process,
/api to the Express PM2 process, the admin subdomain to the static
Vite build, and /uploads to the images folder. Safe to commit —
contains no secrets.
.gitignore Keeps .env files, node_modules, build output, and uploaded
images out of Git — see the note below.
README.md Setup instructions: environment variables needed, how to run each
app locally, and the deploy steps for the VPS.
docs/ Every planning document produced so far — SRS, PRD, design
direction, engineering rules, phases, and this folder structure —
versioned alongside the code.
Why .env is real but never committed: .env holds actual secrets — the live MongoDB connection string,
Redis URL, SMTP credentials, and eventually the Habib Metro gateway keys. If it were committed, anyone
with repository access would have live credentials to the database and payment gateway. .env.example is the
safe, committed template — same variable names, no real values — so anyone setting up the project knows
exactly what needs to be filled in without ever seeing the actual secrets.
How This Maps to Hosting
Three things run on the VPS, coordinated by Nginx and PM2 exactly as already planned:
apps/web Built and run as a Node process (`next start`), kept alive by PM2 via
ecosystem.config.js. Nginx reverse-proxies the storefront domain to it.
apps/admin Built once (`vite build`) into static files; Nginx serves them directly — no running
process needed for this one.
server Runs as a second Node process under the same PM2 file. Nginx reverse-proxies
/api requests to it, and serves /uploads directly from server/uploads/ as static files.
Redis and MongoDB Atlas sit alongside this: Redis runs locally on the VPS (or a small managed instance)
since the API talks to it constantly and low latency matters; MongoDB stays on Atlas as already decided.
